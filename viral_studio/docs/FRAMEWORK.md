# 爆款视频复刻：智能体框架

（万镜一刻 · viral_studio）

## 1. 任务与思路

爆款复刻要解决的问题：投放团队知道一条视频为什么火，但这份判断力存在人脑里，换一个商品、换一组模特，就得重新开会、重新拍。这套框架把"会拍爆款"变成可执行资产——**爆款拆成拍法，拍法沉淀成卡片，卡片组合成成片**。输入一份商品说明加几张人物图，产线跑完直接出片。

成片沿用行业通用的三段式骨架：钩子（前几秒留住人）、展示（把卖点讲透）、转化（引导下单）。每个段位备有若干张"技能卡"，一张卡就是一种拍法的完整封装：适用条件、生成管线、提示词模板、文案槽位、实测参数。

框架由四个 Agent 组成：理解（拆解爆款、蒸馏成卡片，已设计待接入）、编剧（选卡、写稿）、导演（编译成调用计划并校验、失败时决策）、执行（生成与组装）。LLM 只出现在三处——挑卡片、写文案动作、执行失败超出已知模式时的决策；主干全部是确定性代码。这个分工不是偏好，是成本结构决定的：视频生成按秒计费且不可撤销，凡是能在花钱之前测出来的，绝不留给运气。

## 2. 框架概述

```
商品 brief + 人物图/商品图
    │
    ▼
编剧 Agent ── 选卡(LLM) ──→ 写稿(LLM: 台词/旁白/动作) ──→ 分镜脚本
    │
    ▼
导演 Agent ── 确定性编译: 占位符落定 ──→ 逐步调用计划; 计划校验
    │
    ▼
预检闸门 ── 14 类确定性检查, 有错拒绝进入付费执行
    │
    ▼
执行器 ── 远程生成(可灵/animate/TTS/音乐) + 本地组装(落位/字幕/混音)
    │
    ▼
成片 + 逐步执行台账
```

几条贯穿性的设计规则，均出自真机踩坑：

**点单高于品味。** brief 里的 `skill_overrides` 可以钉死某个段位用哪张卡，没点名的段位才轮到 LLM 挑。运营指定拍法是常态需求，不能让模型的审美挡路。

**卡片所见即所得。** 管线里写了什么步骤就执行什么步骤，框架不暗中插入任何环节。早期版本曾在缺背景图时自动前置一步生成，排查问题时没人想得到它的存在，此后废除。

**预检前置。** 可灵的时长只收 3–15 的整数、图片引用编号不能超过挂图数量、中文口播按 5 字/秒塞不进镜头窗就必然穿帮——这类失败在提交前全部可判。预检有错，执行器拒绝启动。

**指纹绑内容。** 每步产物按（段落, 步骤）命名，签名由参数与上游指纹递归算出，断点续跑只补缺的部分，已付费素材不重买。一次事故教会我们把签名绑在内容上而不是参数上：护栏复用旧产物时若记下新签名，账本即被投毒，后续重跑会把陈旧的拼装当成品复用。

**一步失败不丢整段。** 视频生成又慢又贵，链路末端全是廉价后期。配乐失败就回退到本段最后一个成品画面；某一镜被拒就用同人的成功镜头等长补位——跳镜会让后面所有切点错拍，补位才保得住节拍网格。

## 3. 模块功能

**技能卡库（SkillStore）。** 卡片一律 YAML，按类目、人数、段位、商品绑定四个维度筛候选。商品绑定解决资产污染：有的卡内嵌商品专属素材（驱动片段、景别参考图），换商品若仍被选中，开场会拍出上一个商品的人和衣服。

**编剧（StoryboardPlanner）。** 两次 LLM 调用：先在候选卡中为主体段选型并给出理由，再按选定卡片的槽位逐条写稿——台词、旁白、标题、英文动作编排。曾试过一次调用输出嵌套结构，模型把内层 JSON 写成字符串且三轮修不回，此后拆成两步、只收平铺输出。写稿配四层护栏：字数按语言计（中文数字、英文数词）；高危动作词表（旋转跳跃类实测易崩）；道具越界检查（画面里只有身上一件衣服，不许凭空多出第二件）；`must_match` 句式约束（双人卡强制 the woman in white 指名道姓）。所有违规逐条喂回重试——早期只回传字数，定性违规的句子反被标"保持原样"，模型四轮原地踏步。

**导演（ActAgent）。** 承接分镜脚本，产出逐步调用计划。刻意的双路设计：正常路径零 LLM——确定性编译把占位符全部落定（`$hook_N` 人物图、`$item_N` 商品图、`$skill.assets.*` 卡内资产、`{slot}` 文案、`@id` 运行期产物引用），计划除 `@` 引用外无一悬空，可整单人工审阅、可复现；配套校验器把关工具是否注册、必填参数是否齐、`@` 引用是否可达。LLM 只留在异常路径：失败模式有限且已知（NoHuman/FullFace/审核/网络/超时），规则内的按实测规则处理，规则之外才让模型判断该重试、换参、降级还是跳过。

**预检（pretest）。** 14 类检查覆盖提示词方言、时长域、语速窗、文件存在性、时间轴连续性、槽位对齐等。每条对应一次真实翻车，新坑修完就固化成一条检查，让它只坑一次。

**执行器（Executor）。** 按段执行计划，远程后端懒加载——计划没用到的路线不因缺密钥报错。失败分类处理：前置检测类拒绝（NoHuman/FullFace）是确定性的，不重试；网络类重试一次。台账逐步记录耗时、任务号、失败原因。

**本地工具集。** 落位拼装、混音、字幕、卡点强化等约十个工具，参数皆为实测钉死：demucs 必须走 CPU（MPS 卷积通道超限）；字幕由 Pillow 渲染后叠加——生成模型写中文不可靠，自己写的字才百分之百准确；人声先响度归一再混 BGM（各段实测相差 11dB）。

## 4. 技能卡举例

**beat_pose_reel（资产驱动型 · 开场）。** 源头是一条 13 秒切 13 刀、12 个切点全部命中音乐重音的爆款。拆解发现其内容是静态的——一人一套衣一个场景，动感全部来自剪辑。复刻分工：预处理按帧号把原片硬切成 9 镜（边界逐帧裁决，杜绝串帧）；短于 2 秒的镜头回文补帧过生成接口的时长地板，落位时只取正放部分；每镜用 animate 迁移动作，参考图按近/中/全身三档分配——实测输出取景跟随参考图而非驱动视频，景别只能在参考图上造。BGM 直接沿用原片音轨，切点时序原样保持，卡点零成本继承。拼装实测 10/12 个切点偏差不超过 0.017 秒。

```yaml
assets:
  bgm: memory/assets/yike_pose/bgm.m4a
  slot_durations: [0.833, 0.6, 0.567, 1.0, 1.233, 2.3, 0.433, 0.533, 1.067]
  ref_close: memory/assets/.../ref_close.png   # 三档景别参考图, 与卡绑定
pipelines:
  "1":
    - {id: s01, tool: animate_move, optional: true,
       params: {ref: $skill.assets.ref_close, driving: $skill.assets.shot_01}}
    # ... s02–s09, 各镜按档位取参考图 ...
    - {id: asm, tool: assemble_slots, local: true, lenient: true,
       params: {videos: ["@s01", ...], durations: $skill.assets.slot_durations}}
    - {id: mixed, tool: mix_audio, local: true,
       params: {video: "@asm", bgm: $skill.assets.bgm, duration: 8.566}}
```

**outdoor_narration（模板型 · 主体）。** 每人 10 秒户外场景，声画解耦：画面无声生成，旁白单独 TTS，字幕后期烧录。动作不写死在卡里——写稿 LLM 在同一次调用里产出旁白与英文动作编排，二者互相呼应（旁白讲印花时，画面动作正是低头看印花）。5 字/秒的语速窗写进预检，台词塞不进镜头窗在花钱之前就报错。

**sequential_reveal（收尾型 · 多人同框）。** 多人依次入镜或双人共舞收尾。两条实测约束写死在提示词里：所有人同尺寸同景深，否则后入者会以"照片卡片"形式出现且偏小；音乐多生成 2 秒、砸点后裁到段长加 0.55 秒衰减——否则最后一击被后段音频覆盖，成片里等于消失。
