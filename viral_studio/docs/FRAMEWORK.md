# 爆款视频复刻智能体框架技术文档

## 1. 概述

本框架用于短视频广告的自动化复刻生产：将已验证的爆款视频拆解为可复用的拍摄方法（技能卡），由智能体根据商品信息选择拍法、生成文案并完成视频生产。输入为商品说明与人物、商品参考图，输出为完整成片。

成片采用三段式结构：钩子段（开场吸引）、展示段（卖点呈现）、转化段（引导下单）。每个段位对应若干技能卡；一张技能卡完整封装一种拍法，包含适用条件、生成管线、提示词模板、文案槽位与经过验证的参数。

框架由四个 Agent 构成：

- 理解 Agent：拆解爆款视频并蒸馏为技能卡（已完成设计，待接入）；
- 编剧 Agent：选择技能卡，生成台词、旁白与动作描述；
- 导演 Agent：将分镜脚本编译为可执行调用计划，负责计划校验与执行失败决策；
- 执行 Agent：调度远程生成与本地合成，产出成片。

LLM 仅用于三个环节：技能卡选择、文案生成、超出既定规则的失败决策；其余环节均为确定性代码实现。该设计基于成本约束：视频生成按时长计费且不可回滚，所有可静态判定的错误均应在提交前拦截。

## 2. 处理流程

```
商品 brief + 人物图/商品图
    ↓
编剧 Agent：选卡（LLM）→ 写稿（LLM）→ 分镜脚本
    ↓
导演 Agent：确定性编译 → 逐步调用计划 + 计划校验
    ↓
预检：14 类静态检查，存在错误则不进入执行
    ↓
执行 Agent：远程生成（视频/语音/音乐）+ 本地合成（拼装/字幕/混音）
    ↓
成片 + 执行台账
```

主要设计原则：

1. **策略可指定。** brief 中的 `skill_overrides` 字段可指定各段位使用的技能卡；未指定的段位由 LLM 在候选中选择。用于满足运营侧指定拍法的需求。
2. **管线显式化。** 调用计划的每一步均在技能卡中显式声明，框架不隐式插入处理环节，保证计划可审查、可复现。
3. **静态检查前置。** 生成接口的参数约束（时长取值范围、图片引用编号上限、口播语速与镜头时长的匹配等）均可在提交前判定；预检不通过则不进入付费执行。
4. **产物签名与断点续跑。** 每步产物按（段落，步骤）命名，签名由参数与上游签名递归计算；重跑时仅执行签名变化的步骤，已生成素材不重复计费。签名与产物内容绑定，防止参数变更后复用过期产物。
5. **失败降级。** 单步失败不废弃整段：后期步骤（配乐、字幕）失败时回退至该段最后一个可用画面；单镜头生成被拒时以同人物的成功镜头按原时长补位，保持切点时间轴不变。

## 3. 模块说明

**技能卡库（SkillStore）**。技能卡以 YAML 定义，按商品类目、人物数量、段位、商品绑定四个维度筛选候选。商品绑定用于内嵌专属素材（驱动片段、景别参考图）的卡片，防止跨商品误用。

**编剧 Agent（StoryboardPlanner）**。两次 LLM 调用：第一次完成主体段选型并输出选择理由；第二次按选定卡片的槽位生成文案，包括台词、旁白、标题与英文动作描述。采用两次调用而非单次嵌套输出，原因是嵌套 JSON 输出的稳定性不足。文案生成配有四类校验：字数按语言分别计数（中文按字、英文按词）；高风险动作词过滤（旋转、跳跃等生成质量不稳定的动作）；道具一致性检查（不允许出现参考图之外的服装或道具）；句式约束（`must_match` 正则，如双人场景要求以具体人物指代开头）。校验不通过的条目连同具体问题反馈至下一轮重写，直至收敛。

**导演 Agent（ActAgent）**。正常路径为确定性编译：将占位符（`$hook_N` 人物图、`$item_N` 商品图、`$skill.assets.*` 卡内资产、`{slot}` 文案、`@id` 运行期产物引用）替换为实际值，输出逐步调用计划；配套校验器检查工具注册、必填参数、引用可达性。LLM 仅用于异常路径：失败类型可枚举（人物检测失败、内容审核、网络异常、超时），规则内的失败按既定策略处理，规则外的由 LLM 判定重试、调参、降级或跳过。

**预检（pretest）**。14 类静态检查，覆盖提示词格式、时长取值域、口播语速与镜头窗匹配、素材文件存在性、时间轴连续性、槽位对齐等，作为付费执行前的强制关卡。

**执行 Agent（Executor）**。按段执行调用计划。远程后端（可灵、animate、TTS、音乐生成）按需加载，计划未使用的路线不要求配置密钥。失败按类型处理：前置检测类拒绝（NoHuman/FullFace）为确定性结果，不重试；网络类错误重试一次。执行过程逐步记录耗时、任务号与错误信息。

**本地工具集**。拼装、混音、字幕、卡点强化等约十个工具，关键参数均经实测确定：人声分离固定使用 CPU 推理；中文字幕由本地渲染后叠加，不依赖生成模型输出文字；人声混音前统一响度归一。

## 4. 技能卡示例

**beat_pose_reel（资产驱动型 · 开场段）**。源自一条 13 秒 13 个镜头、切点与音乐重音对齐的爆款。该卡将原片按帧号切分为 9 个驱动片段，逐镜头进行人物动作迁移；参考图按近、中、全身三档景别分配（实测生成画面的取景由参考图决定）；不足 2 秒的片段以回文方式补帧至接口时长下限，合成时仅取原始正放部分；背景音乐沿用原片音轨，保持原切点时序。合成后切点位置误差不超过 0.017 秒（10/12 个切点）。

```yaml
assets:
  bgm: memory/assets/yike_pose/bgm.m4a
  slot_durations: [0.833, 0.6, 0.567, 1.0, 1.233, 2.3, 0.433, 0.533, 1.067]
  ref_close: memory/assets/.../ref_close.png   # 三档景别参考图, 与卡绑定
pipelines:
  "1":
    - {id: s01, tool: animate_move, optional: true,
       params: {ref: $skill.assets.ref_close, driving: $skill.assets.shot_01}}
    # s02–s09 同构, 按景别档位取参考图
    - {id: asm, tool: assemble_slots, local: true,
       params: {videos: ["@s01", ...], durations: $skill.assets.slot_durations}}
    - {id: mixed, tool: mix_audio, local: true,
       params: {video: "@asm", bgm: $skill.assets.bgm, duration: 8.566}}
```

**outdoor_narration（模板型 · 展示段）**。每人 10 秒户外场景，采用声画分离方案：画面静音生成，旁白由 TTS 单独合成，字幕后期本地烧录。旁白与动作描述由编剧 Agent 在同一次调用中生成，保证二者内容对应。口播语速按 5 字/秒校验，超出镜头时长的台词在预检阶段报错。

**sequential_reveal（收尾型 · 转化段）**。多人依次入镜或双人共舞。提示词中固化两条经验参数：多人场景需声明同一比例与景深，否则后入镜人物易被渲染为缩小的卡片形态；音乐生成时长比段长多 2 秒，重音强化后裁剪至段长加 0.55 秒衰减尾，防止段落拼接时末尾重音被截断。
