### Mix chain — `tools/audio/audio_mixer.py` (735 lines)
Operations `mix|duck|extract|full_mix|segmented_music` (line 51). Concrete numbers:
- **Ducking** (`_duck` line 332, `_full_mix` line 471): ffmpeg `sidechaincompress=threshold=0.02:ratio=9:attack=0.2:release=0.5:level_sc=1:mix=0.9` with speech as key (lines 409-415, 571-576); defaults `music_volume_during_speech=0.15` (~-16.5dB), `attack_ms=200`, `release_ms=500` (lines 127-130); simple API `duck_level=-12` dB → linear via `10^(dB/20)` (lines 369-376); post-duck `volume={music_vol*3}` sidechain-level compensation (line 413).
- **Loudness** (`_loudnorm_filter` line 198-214): `loudnorm=I={target}:LRA=11:TP=-1.5`, default **-16 LUFS** (Apple Podcasts), **-14 for YouTube/TikTok/IG**, forwarded from `edit_decisions.metadata.loudnorm_target` (lines 134-147).
- **`full_mix`** is the one-call preferred op for compose: speech amix → `asplit` into sidechain key + output branch → duck music → add SFX → loudnorm (lines 534-604).
- **`segmented_music`** (line 629): music only inside `{start,end}` segments via per-frame `volume` expression, `music_volume=0.20` default, `fade_duration=0.5s`, `amix ... normalize=0` so speech passes at unity (lines 691-703), `-stream_loop -1` music looping, video `-c:v copy` + AAC 192k — **this is the exact shape of a Maestro assemble-step bolt-on** (takes an already-assembled mp4).
- `audio_enhance.py` presets (lines 24-80): `clean_speech` = `highpass=f=80,lowpass=f=13000,agate=threshold=0.01:ratio=2,acompressor=threshold=-20dB:ratio=3:attack=5:release=100,loudnorm=I=-16:LRA=11:TP=-1.5`; `voice_clarity` = cut 200Hz -3dB, boost 3kHz +3dB, 5kHz +2dB; `broadcast` = `loudnorm=I=-24:LRA=7:TP=-2` + `alimiter=limit=0.95`.

### `skills/creative/sound-design.md` — the numbers (quick-ref card lines 8-18)
Dialogue **-12 dB peak / -16 to -14 LUFS**; music bed **-30 to -20 dB (18-20 dB below dialogue)**; SFX -18 to -12 dB; **whoosh starts 10-20ms BEFORE the visual, 400-500ms long** (line 73: "brain processes audio faster"); true peak **never above -1.5 dBTP**; W3C: music 20 dB under speech; BBC: drop music another 4 dB from where it "sounds right"; duck 6-12 dB normally, up to 22 dB for complex educational; EQ-cut 2-4 kHz on music to clear the voice band (lines 29-34). Music BPM by content: calm 60-80, standard 90-110, upbeat 120-140, action 140-200 (lines 38-45). AI-TTS chain (lines 104-121): HPF 80-100Hz, cut ~500Hz, boost 2-5kHz +2-3dB, cut 6-8kHz, compression 3:1 attack 1-5ms release 10-20ms threshold -26dB, limiter -1.5dBTP. Platform table (lines 78-87): everything -14 LUFS except Apple Podcasts -16.

### `skills/meta/voice-performance-director.md` — TTS direction contract
Every narration script must carry a top-level `voice_performance` object (`performance_intent`, `pacing_profile`, `energy_curve`, `pause_policy`, per-provider notes) and section-level `delivery_cues` (`pace`, `energy`, `emphasis_words`, `pause_before/after_seconds`, `provider_text` with SSML breaks) — lines 9-42. "Read naturally" alone is a **quality failure** (lines 83-94). Sample gate before batch generation (lines 73-81). Provider mapping: OpenAI `gpt-4o-mini-tts` `instructions` field; Google SSML `<break>`; ElevenLabs lower `stability` + moderate `style` (lines 56-70).

### `.agents/skills/music-to-video/` — beat-sync machinery
`scripts/analyze-beatgrid.py` (532 lines, librosa+numpy+soundfile, no learned models): decodes to mono 22050Hz/HOP 512 (~23ms frames), librosa beat-track → BPM/beats, downbeat phase = bar phase with max kick energy (lines 93-103), 16th-note grid classification strong/weak/syncopated/off-grid (lines 106-130), drum typing by band-split flux (kick <150Hz, snare 150-900Hz, hihat ≥5kHz, lines 76-81), RMS@1s energy phases VOID<0.2/LOW<0.4/MEDIUM<0.65/HIGH (line 180), SURGE/DROP moments at |Δ|>0.12, hard stops (drop < -0.25 in back third), rolls (≥4 onsets, mean spacing < 0.42×beat), silences, 4-bar phrases, per-phase density budgets (sparse/medium/dense at <6 / <18 / ≥18 onsets) → deterministic `audiomap.json`. `SKILL.md`: "One analyzer, and you trust it… never re-measure beats with another tool or by ear"; BPM/beat grid trusted **only when music is genuinely rhythmic**, else pace by phrases (`pacing: beat_cut | phrase_flow`). Directly reusable in Maestro if music is generated first and shots are cut to the beat grid.

### Seedance native audio
`tools/video/seedance_video.py`: `generate_audio` bool param "Generate synchronized audio (speech, SFX, ambient)" (lines 107-110), passed straight to fal.ai payload (209-210), **defaults True** (line 314); `reference_audio_urls` ≤3 clips as "voice / music / ambience anchors" (139-144, 240-251). `.agents/skills/seedance-2-0/SKILL.md`: "Single-pass native synced audio … Speech + SFX + ambience generated jointly, not post-sync" (line 23); param table: "`generate_audio` | Keep **on** unless you have a specific reason to mute — Seedance's moat is synced audio. Strip audio downstream in compose if needed." Lip-sync guidance **verbatim** (§"Lip-sync from quoted dialogue"):

> ```
> Aang stands on the cliff edge, staff raised, wind in his cloak.
> Aang says: "I won't run anymore."
> Sokka, half a step behind, replies: "Then we fight."
> ```
> Use `Character says: "..."` / `Character replies: "..."` exactly — mouth shapes key off quoted strings. Keep each line under ~6 words; longer lines risk drift on fast clips.

Anti-patterns table: "Write dialogue longer than ~6 words on fast-cut shots → Lip-sync drift"; "Generate music through Seedance audio → Texture-only is fine; for real scoring use `music` / `pixabay_music` / `elevenlabs` and mix in compose". Audio cues that work: ambient (`distant thunder rolling over mountains`), diegetic (`boots crunching snow`), music "light touch only" (`low orchestral swell building`) — "Do **not** request complex multi-instrument scores — keep music language textural."

**Maestro mapping:** per-shot = flip `generate_audio:true` + quoted-dialogue prompting (dialogue/lip-sync/SFX come free from seedance); assemble = `segmented_music`/`full_mix` pattern (music bed + sidechain duck against the seedance dialogue track + `loudnorm I=-14:LRA=11:TP=-1.5`).

## 2. ViMax (`/Users/kevin/Desktop/Kevin/repositories/ViMax`)

**No TTS, no music tool, no mixer, no SFX tool anywhere** — audio is 100% native in-model, per shot. Mechanisms:
- `interfaces/shot_description.py:31-38,158-165`: every shot has an `audio_desc` field — examples `"[Sound Effect] Ambient sound (supermarket background noise, shopping cart wheels rolling)"`, `"[Speaker] Alice (Happy): Hello, how are you?"`. Dialogue is ALSO written into the visual description with the pattern `<SLING> (male, late 20s, Texan accent softened by military precision…) says: "Gear retracted…"` (lines 22, 106, 154 — narration as `Narration: "…"`).
- `agents/script_enhancer.py:33-34`: "For each character in the conversation, repeat the core voice description (e.g., male, early 50s, South African–North American accent) using the same prompt each time" — **voice consistency across shots via repeated verbal voice spec**, since each shot is an independent generation.
- `agents/storyboard_artist.py:49`: "Assign at most one dialogue line per character per shot. Each line of dialogue should correspond to a shot."
- Sync mechanism: `pipelines/script2video_pipeline.py:514` — `prompt = shot_description.motion_desc + "\n" + shot_description.audio_desc` fed to the video generator; `tools/video_generator_openrouter_api.py:67,75` — `generate_audio` env-toggled (`VIMAX_OPENROUTER_GENERATE_AUDIO`, default True) in the payload. The doubao-seedance/veo yunwu generators pass no audio params.
- Assembly: plain `moviepy concatenate_videoclips` (`script2video_pipeline.py:314`, `utils/video.py:26-37`) — native per-shot audio survives concat untouched; zero post-mix.

**Maestro relevance:** ViMax is the proof that Maestro's cheapest dialogue path is prompt-only — quoted dialogue + repeated voice descriptor per shot, `generate_audio:true`, no new infrastructure. Its weakness (no music bed, no loudness control) is exactly what OpenMontage's assemble-stage chain fills.

## 3. univa (`/Users/kevin/Desktop/Kevin/repositories/univa`)

Has a dedicated FastMCP audio server `univa/mcp_tools/audio_gen.py` — notable because it uses **WaveSpeed, Maestro's existing provider**:
- `generate_audio_for_video` (lines 28-121): post-hoc video→audio foley via WaveSpeed **`mmaudio-v2`** (`POST https://api.wavespeed.ai/api/v3/wavespeed-ai/mmaudio-v2`, `utils/wavespeed_api.py:425-471` — payload: prompt + base64 video data-URI, `duration=5`, `guidance_scale=4.5`, `num_inference_steps=25`; config `univa/config/mcp_tools_config/config.yaml:22-31`). Prompt auto-generated by a VLM watching 64 extracted frames (`utils/query_llm.py:432-448`, GPT-5).
- `generate_speech` (lines 124-239): TTS via WaveSpeed-hosted **MiniMax `speech-2.5-turbo-preview`** (`wavespeed_api.py:700` — `POST /api/v3/minimax/speech-2.5-turbo-preview`, params `voice_id="Wise_Woman"`, `emotion`, `pitch`, `speed`, `volume`); text can be auto-written from video content (`speech_prompt_gen`, `query_llm.py:451-468`).
- Sync/mix: `utils/speech_process.py:73-230` `align_and_merge_audio` — **librosa `time_stretch(rate=audio_dur/video_dur)`** to force speech to exactly fit the video (line 131-136), then RMS-based auto volume balance: if one track's RMS > 1.2× the other, scale the louder down by the RMS ratio (lines 175-186), then moviepy `CompositeAudioClip` over the original track. `utils/video_process.py:27-170` `merge_videos(video_paths, audio_list)`: ffmpeg concat with `-an`, concat audio files, mux `-c:v copy -c:a aac`.
- `mcp_tools/video_gen.py:168-186`: per-shot audio integration exists but is **commented out ("TODO: 5.audio integration")** — they planned mmaudio per shot post-generation.

**Maestro relevance:** mmaudio-v2 and MiniMax TTS are callable on Maestro's existing WaveSpeed key — a fallback path for adding foley/dialogue to already-silent generated clips without regeneration (assemble-side), though univa's crude RMS balancing and time-stretch are inferior to OpenMontage's sidechain-duck + loudnorm chain.
