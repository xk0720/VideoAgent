# Cost-Efficient Video Generation: Strategy Catalog (2025–2026)

## 1. Draft-then-refine / resolution laddering — **transfers-cleanly**

The dominant 2025-26 pattern in published model architectures is two-stage generation: cheap low-res base pass, then a dedicated refiner/super-resolution pass — not full-res regeneration.

- **HunyuanVideo 1.5** (Tencent): DiT generates 480p/720p, 5–10s; a "few-step Video Super-Resolution Network" upscales to 1080p, "enhances sharpness while correcting distortions." ComfyUI ships this as a two-stage graph (720p gen → distilled SR → 1080p). Sources: [arxiv.org/pdf/2511.18870](https://arxiv.org/pdf/2511.18870), [github.com/Tencent-Hunyuan/HunyuanVideo-1.5](https://github.com/Tencent-Hunyuan/HunyuanVideo-1.5), [HF discussion on using it purely as an upscaler](https://huggingface.co/Comfy-Org/HunyuanVideo_1.5_repackaged/discussions/2).
- **LongCat-Video** (Meituan): coarse-to-fine on both axes — base 480p/15fps (50 steps, CFG 4.0), trilinear upsample to 720p/30fps, refined by a LoRA "refinement expert" via flow matching + 3D block-sparse attention; claimed >10× inference-efficiency gain. Sources: [arxiv.org/pdf/2510.22200](https://arxiv.org/pdf/2510.22200), [github.com/meituan-longcat/LongCat-Video](https://github.com/meituan-longcat/LongCat-Video).
- **Waver** (ByteDance): refiner takes a 480p/720p first-stage video → 1080p, "identical content, enhanced clarity" ([arxiv.org/pdf/2508.15761](https://arxiv.org/pdf/2508.15761)). **FlashVideo** quantifies why: 30s at 270p vs 2150s at 1080p for a 5B model ([arxiv.org/html/2502.05179v1](https://arxiv.org/html/2502.05179v1)); **SURF** does low-res latent preview → Refiner upscale ([arxiv.org/html/2603.21002](https://arxiv.org/html/2603.21002)).
- **Upscaler-as-finalize, API side**: Maestro's own provider WaveSpeed hosts **SeedVR2** video upscaling — ~$0.15 per 5s at 1080p, $0.25 per 5s at 4K, clips to 10 min, 5s minimum billing ([wavespeed.ai/models/wavespeed-ai/seedvr2/video](https://wavespeed.ai/models/wavespeed-ai/seedvr2/video), [wavespeed.ai/docs/docs-api/wavespeed-ai/video-upscaler](https://wavespeed.ai/docs/docs-api/wavespeed-ai/video-upscaler)). Practitioner guidance for AI-generated clips: skip CNN upscalers (Real-ESRGAN-class) and use SeedVR2 — "hallucinated detail matches the generated distribution better than ESRGAN" ([morphed.app/blog/ai-video-upscaler](https://morphed.app/blog/ai-video-upscaler)). Real-ESRGAN is free/local but tuned for anime/UI content; Topaz is $299/yr subscription ([botmonster.com comparison](https://botmonster.com/ai/local-ai-image-upscaling-real-esrgan-topaz-supir/), [wavespeed.ai/blog/posts/real-esrgan-vs-topaz](https://wavespeed.ai/blog/posts/real-esrgan-vs-topaz/)).

**Maestro fit**: run the whole review/repair loop at 480p (already the test config), and finalize only accepted timelines via one SeedVR2 pass. At Seedance-2.0 standard rates ($0.092/s @480p vs $0.199/s @720p, [evolink.ai pricing guide](https://evolink.ai/blog/seedance-2-0-pricing-api-cost-guide)), a 60s video with 1.5× repair overhead costs ~$8.3 at 480p+~$1.8 upscale vs ~$17.9 at 720p — roughly 45% savings with zero machinery changes. Caveat: upscalers can't fix motion/continuity errors, only sharpness — which is fine, since Maestro's verifier judges continuity, not resolution.

## 2. Fast/turbo tiers and quality deltas — **transfers-cleanly**

- **Seedance 2.0** (Maestro's model, on-provider): EvoLink lists t2v standard $0.092/s (480p) / $0.199/s (720p); **Fast $0.074/s (480p) / $0.161/s (720p)** — ~20% cheaper, "identical quality options," docs explicitly recommend "480p for testing and drafts, 720p for customer-facing finals" ([evolink.ai](https://evolink.ai/blog/seedance-2-0-pricing-api-cost-guide)). Atlas Cloud quotes a wider gap: Fast $0.09/s vs Pro $0.247/s at 1080p, with Fast "genuinely production-ready" and Pro offering "refinements rather than fundamental quality differences" ([atlascloud.ai cheapest-API guide](https://www.atlascloud.ai/blog/guides/cheapest-ai-video-generation-api-2026), [Seedance cost-per-second](https://www.atlascloud.ai/blog/guides/seedance-2-cost-per-second)). Segmind's Pro/Pro-Fast/Lite comparison agrees Fast is the default for bulk work ([blog.segmind.com](https://blog.segmind.com/seedance-pricing-comparison-pro-vs-pro-fast-vs-lite-plans/)).
- **Cross-model table** (Atlas Cloud, 2026): Wan 2.6 $0.07/s (720p, audio), Vidu Q3 $0.07/s, Kling Video O3 $0.085/s, Sora 2 $0.10/s, Hailuo 2.3 $0.10/s, Kling 3.0 $0.153/s, Seedance 2.0 Pro $0.247/s. (Their Veo 3.1 $0.03/s figure conflicts with other sources — [buildmvpfast](https://www.buildmvpfast.com/api-costs/ai-video) and [fluxnote](https://fluxnote.io/guides/ai-video-model-pricing-comparison-2026) put Veo 3.1 Fast at ~$0.15/s and Standard $0.40–0.75/s — treat as unreliable.) Range across market: $0.05–0.75/s; a 10s clip runs $0.50 (Wan 2.6) to $7.50 (Veo 3.1 Standard) ([rangy.ai pricing explainer](https://rangy.ai/blog/ai-video-pricing-explained/)).

**Maestro fit**: two-lane routing — Fast tier for drafts, exploration windows, and repair-loop candidate regens; Standard/Pro only when the A/B verifier rejects a Fast render for quality (not continuity) reasons. Zero-code-change portion: flip the WaveSpeed model slug per attempt number.

## 3. Keyframe-first / storyboard gates — **needs-adaptation**

- **DrawVideo** decomposes long video into storyboard shots controlled by sketches + prompts before video spend ([arxiv.org/html/2605.23508](https://arxiv.org/html/2605.23508)); **CineLOG** is training-free cinematic long-video via hierarchical planning ([arxiv.org/pdf/2512.12209](https://arxiv.org/pdf/2512.12209)); **Generative Inbetweening** adapts i2v models for keyframe interpolation ([arxiv.org/abs/2408.15239](https://arxiv.org/abs/2408.15239)).
- **FLF2V (first+last frame)** is now commodity across Kling 3.0/O1, Wan, Seedance, Hailuo: provide frame A and B, model interpolates; primary use is scene transitions and chaining clips via last-frame→first-frame ([comfy.org Kling FLF2V workflow](https://comfy.org/workflows/api_kling_v3_flf2v-351e79d06ae1/), [fal.ai/models/fal-ai/kling-video/o1/image-to-video](https://fal.ai/models/fal-ai/kling-video/o1/image-to-video), [wavespeed.ai FLF landing](https://wavespeed.ai/landing/models/first-last-frame-video-models)).
- **Storyboard-preview gating in products**: LTX Studio's define→storyboard→generate→edit flow lets users approve still storyboards and shot descriptions *before* burning generation credits ([ltx.io/studio/platform/ai-storyboard-generator](https://ltx.io/studio/platform/ai-storyboard-generator), [dupple.com/reviews/ltx-studio](https://dupple.com/reviews/ltx-studio)).

**Maestro fit (needs-adaptation)**: t2i keyframes cost ~$0.01–0.04 vs ~$0.5–1 per video attempt, so having the brain approve keyframes (or having Gemini review a keyframe against the shot spec) before any video call converts video-retry failures into image-retry failures at ~20× lower unit cost. This slots naturally into Maestro's existing first-frame-lock and reference-channel strategies — the keyframe becomes the conditioning asset. FLF2V additionally gives a cheap, deterministic transition-shot strategy (candidate 9th menu item). Adaptation needed: keyframe approval can't catch motion-quality failures, so it reduces but doesn't replace VLM video review.

## 4. Best-of-N vs repair-loop economics; probe gates — **needs-adaptation**

- **ViMax** (agentic long-video pipeline, closest published analog to Maestro) samples k candidates in parallel and uses a VLM judge for best-of-k against shot-planning requirements (fidelity, narrative consistency, spec adherence) ([arxiv.org/pdf/2606.07649](https://arxiv.org/pdf/2606.07649)). The **Test-Time Scaling in Multimodal Foundation Models survey** frames best-of-N with MLLM-as-judge as the standard mechanism, and notes evaluator sets should be selected per-input, not fixed ([arxiv.org/pdf/2606.08231](https://arxiv.org/pdf/2606.08231)).
- **SWIFT** ("Can Test-Time Scaling Improve World Foundation Model?") is the key economics result: process-level strategies — probability-based Top-K **pruning of partial rollouts** and beam search — beat naive best-of-N at equal compute; small models + TTS rival larger models ([arxiv.org/abs/2503.24320](https://arxiv.org/abs/2503.24320)). **Anchored Tree Sampling** similarly keeps a small pool of promising continuations per step instead of greedy single-candidate long-horizon generation ([arxiv.org/pdf/2605.20476](https://arxiv.org/pdf/2605.20476)).
- No published head-to-head of "2×candidates+select" vs "1+repair" for API video exists; the arithmetic: 2 candidates = guaranteed 2.0× spend; repair loop = 1.0× when first-pass acceptance is high. Best-of-2 wins only for shots whose historical first-pass reject rate exceeds ~50%, or when repair itself usually triggers full regen.

**Maestro fit**: (a) make N adaptive per-shot — brain flags "risky" shots (complex motion, new scene) for best-of-2-Fast, everything else 1 candidate + existing repair loop; (b) **probe gates**: Seedance bills per output second with a 5s minimum on WaveSpeed-style billing, so generate the 5s minimum (or first segment) of a long shot, VLM-check it, then video-extend — Maestro's video-extend strategy already makes the probe reusable as the shot's head rather than sunk cost. That is SWIFT's partial-rollout pruning translated to API calls.

## 5. Caching / reuse / partial regeneration — **transfers-cleanly**

- ComfyUI's execution model is the reference design: content-addressed graph caching where unchanged nodes never recompute, with `IS_CHANGED` invalidation on seed/file/time ([deepwiki.com ComfyUI graph execution & caching](https://deepwiki.com/hiddenswitch/ComfyUI/4.2-graph-execution-and-caching)); TeaCache caches intermediate diffusion outputs for Wan video ([comfyai.run WanVideoTeaCacheKJ](https://comfyai.run/documentation/WanVideoTeaCacheKJ), [neurocanvas.net/blog/teacache-with-comfyui](https://neurocanvas.net/blog/teacache-with-comfyui/)); rgthree provides seed-reuse QoL ([bitsminds ComfyUI guide](https://www.bitsminds.com/guides/comfyui-stable-diffusion-advanced-guide)).

**Maestro fit**: hash (model, prompt, conditioning assets, seed, duration, resolution) → clip path, so brain re-plans, verifier re-runs, and orchestrator crashes never re-bill an identical WaveSpeed call; keep rejected candidates cached as future reference-channel assets. Maestro's cascade-free segment regen (commit 53afe61) is already the partial-regeneration half of this. Diffusion-step caching (TeaCache) is **doesn't-fit** for API usage — provider-side only.

## 6. Open-source local tier — **needs-adaptation** (likely doesn't-fit near-term)

- Wan 2.2 1.3B runs on 8–16GB VRAM; the broadcast-quality 14B needs 40–48GB (FP8, 480p) to 65–80GB (720p) ([willitrunai.com VRAM guide](https://willitrunai.com/blog/wan-2-2-vram-requirements), [runaihome.com GPU guide](https://runaihome.com/blog/wan-video-local-ai-gpu-guide-2026/)). Near-zero marginal cost vs $0.10–1.00/s API; a 10s 1080p API clip ≈$1.50+ ([insiderllm.com local-AI-video guide](https://insiderllm.com/guides/local-ai-video-generation/), [aimagicx.com Wan/Hunyuan/LTX comparison](https://www.aimagicx.com/blog/open-source-ai-video-models-comparison-2026)). Reported quality: Wan 2.2 "comparable to mid-tier commercial APIs for many prompts but worse on complex motion and multi-scene clips" ([insiderllm](https://insiderllm.com/guides/local-ai-video-generation/)); LTX-2 trades quality for speed ([neurocanvas Wan-vs-LTX](https://neurocanvas.net/blog/wan-2-2-vs-ltx-2-comparison/)). SaladCloud benchmarked WAN2.1 per-video cloud-GPU costs ([blog.salad.com/benchmarking-wan2-1](https://blog.salad.com/benchmarking-wan2-1/), page 403s to fetchers).

**Maestro fit**: as a *draft* tier only — local Wan/LTX drafts for brain/verifier plumbing tests and prompt iteration, API Seedance for finals. But it breaks Maestro's continuity machinery: video-extend and reference conditioning are model-specific, so cross-model draft→final doesn't preserve conditioning semantics. Worth it only at high monthly volume with a GPU already owned; otherwise Seedance Fast @480p ($0.074/s) is close enough to make local ops overhead net-negative.

## Priority summary for Maestro
1. **480p-everything + SeedVR2 finalize** (transfers-cleanly, ~40-55% savings, on-provider).
2. **Fast-tier default, Standard on quality-rejects** (transfers-cleanly, 20–60% on generation spend).
3. **5s probe + video-extend commit** (needs-adaptation, kills long-shot full-duration waste; SWIFT-backed).
4. **Keyframe pre-approval via existing first-frame-lock path** (needs-adaptation).
5. **Content-addressed clip cache + seed logging** (transfers-cleanly, engineering-only).
6. **Adaptive best-of-2 only for historically risky shots** (needs-adaptation; flat best-of-N doesn't-fit).
7. **Local open models** (doesn't-fit for finals; optional dev-loop draft tier).
