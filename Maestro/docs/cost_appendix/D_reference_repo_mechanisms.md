## Detail

### 1. OpenMontage

**Cost ledger** (`/Users/kevin/Desktop/Kevin/repositories/OpenMontage/tools/cost_tracker.py`). Every paid op follows `estimate()` (line 101) → `reserve()` (117) → `reconcile()` (164) or `refund()` (173), persisted to `cost_log.json` (487-507). `reserve()` enforces three gates: single-action approval threshold, default $0.50 (`ApprovalRequiredError`, 127-132); first-paid-use-of-tool approval (135-140); and budget check against `usable_budget_usd` = remaining − 10% holdback (87-90), raising `BudgetExceededError` in CAP mode or annotating a warning in WARN mode (143-152). Modes are OBSERVE/WARN/CAP (`lib/config_model.BudgetMode`, imported line 19). `estimate_from_reference` (183-398) bakes in a **`retry_multiplier = 1.3`** (line 273, "~30% extra for retries and rejected outputs"), emits a low/high cost range (368-369), and a **`sample_cost_usd`** for a 2-scene sample (371-374) — directly reusable for Maestro's repair-loop budgeting where retries are the dominant cost.

**Clip cache** (`tools/video/clip_cache.py`). `try_link(clip_id, dest)` (line 318) hard-links a cached blob into the project (copy fallback, `_link_or_copy` 523-543) and bumps LRU `last_access_at`; `ingest()` (367) adds fresh downloads. JSONL manifest rewritten atomically via `os.replace` (290-312), `filelock`-guarded (214-255), LRU eviction at 20 GB default (`_DEFAULT_MAX_TOTAL_BYTES` line 80, eviction 478-515), stale-entry self-healing (337-343). For Maestro: key on content hash of (prompt, strategy, conditioning refs, seed) so a full-regen rerun or A/B-rejected repair never re-pays for an identical clip.

**Pre-spend plan validators** — all zero-LLM, pure-Python, run before any generation dollar: `lib/slideshow_risk.py` `score_slideshow_risk()` (26-87) scores 6 dimensions 0-5 (repetition, decorative visuals, weak motion, weak shot intent, typography over-reliance, unsupported cinematic claims; scorers at 90-255); verdict `fail` at ≥4.0 "should not proceed to compose" (lines 14-18). `lib/delivery_promise.py` locks a `DeliveryPromise` at proposal time (dataclass 82-111); `PROMISE_RULES` (30-79) set `min_motion_ratio` floors (e.g. motion_led = 0.7); `validate_cuts()` (113-193) counts real motion vs "animated slides" vs stills (`_SLIDE_GRAMMAR_TYPES` 128-133) and blocks silent downgrade to still-led without explicit `approved_fallback` (178-184). `lib/variation_checker.py` `check_scene_variation()` (26-176) runs 8 structural checks (shot-size dominance >50%, ≥3 consecutive same-size runs 62-74, static overuse >60%, lighting variety, hero-moment presence/distinctness, generic-phrase blacklist 17-23, texture keywords, shot_intent coverage), score = violations × 0.6 (160). In Maestro these slot after scene_write: reject a bad window plan for $0 instead of discovering it in Gemini review after Seedance spend.

**Sample sub-stage** (`pipeline_defs/cinematic.yaml:103-112`): inside the proposal stage, a `sample` sub-stage renders a "10-15 second cinematic preview for reference-driven productions", conditioned on `video_analysis_brief_exists`, with `human_approval_default: true` and its own limited tool list — an approval gate on tone/palette/music before full-length spend. Same file also caps orchestration: `budget_default_usd: 2.00`, `max_revisions_per_stage: 3`, `max_send_backs: 3`, `max_wall_time_minutes: 12` (lines 26-29). Maestro equivalent: generate window 1 (or a 1-shot sample) and gate the remaining windows on its review verdict.

**Seedance fast-variant pricing** (`tools/video/seedance_video.py`): `estimate_cost` (170-175) rates `fast` at **$0.2419/s vs standard $0.3034/s** (~20% cheaper); `estimate_runtime` 60 s vs 120 s (177-179); fast routes to `bytedance/seedance-2.0/fast/{operation}` (196-197); resolution enum includes 480p (102-106); `idempotency_key_fields = ["prompt", "model_variant", "operation", "duration", "seed"]` (156) — a ready-made cache key. Maestro could run first-attempt/repair candidates on `fast` and only pay standard for the final accepted take.

**Zero-key demo** (`render_demo.py:1-36`): curated Remotion demos as JSON props in `remotion-composer/public/demo-props/`, rendered locally with no API key — a pattern for exercising composition/stitch logic free.

### 2. NEWTON — condition pre-judge

`GeminiVerifierCore.judge_condition` (`/Users/kevin/Desktop/Kevin/repositories/NEWTON/tools/video_verifier/core.py:312-370`) spends one cheap Gemini call (`gemini-3.1-flash-lite`, line 35; temperature 0, line 184) to veto a generation **before** the expensive video-gen call. Inputs: baseline video inline (334-335), proposed sim reference video (337-342), each reference image (343-349), the exact text prompt appended to the instruction (352-353), a text-only fallback note when no visual conditioning exists (354-357), and full attempt history (358-359). Prompt `_COND_INSTRUCTION` (89-134) is the key IP: judge the sim ref **purely on motion/count** and never on appearance ("IGNORE the sim's colors… must NEVER be a reason to reject", 105-108; the sim-vs-images mismatch is "EXPECTED and is NEVER a problem", 115-121); "Be pragmatic, not perfectionist… Only reject when there is a real, fixable problem that would waste the generation" (125-128); output strict JSON `{reasonable, reason, suggestions[]}` (129-133). Wiring in `loop/run_loop.py`: adapter at 616-629 (i2v first/last keyframes are shown to the judge as images too, 620-623); the state machine (744-828) only advances `need_condition → generate` when `judge["reasonable"]` (819-821); on rejection the planner gets reason + suggestions and "no video was generated yet" (823-827); the check **fails open** on exception (786-787); conditioning is carried forward regardless of verdict so rejected-but-good sims aren't rebuilt (813-818); rejected conditions are archived per-turn (791-800). History string built by `Memory.for_condition_judge()` (`loop/memory.py:70-114`) — every prior generation's blind-A/B score + remaining issues and every prior **rejection** with its reason, "so the judge can spot a proposal that repeats a path already shown not to work." The companion blind A/B `verify_relative` (240-309, randomized slot order 272-277, `REL_STOP_THRESHOLD = 5` line 38, 18 MB inline cap line 41) matches what Maestro already runs. Plug-in: between Maestro's condition-strategy pick and Seedance generate — judge the chosen strategy + refs + prompt against the previous shot's tail, fed the repair-ledger history; each veto saves one full 480p Seedance generation for one flash-lite call.

### 3. ViMax

**Path-exists resume everywhere** (`pipelines/script2video_pipeline.py`): every artifact — final video (304-306), transition videos (361-363), camera images (378-380), frame prompts (400-404, 552-556), video clips (497-499), frames (535-537), camera tree (597-602), characters (624), portraits (650, 687-706), storyboard (746), shot descriptions (795) — is `os.path.exists`-checked and skipped. Even LLM selector outputs are checkpointed to JSON (551-567). A crashed or re-run pipeline re-spends $0. Maestro should checkpoint every window-loop artifact the same way.

**Camera-tree reuse**: shots are grouped into cameras (`_group_shots_into_cameras`, line 39); `construct_camera_tree` (590-614, agent at `agents/camera_image_generator.py:122`) links child cameras to parents; a new camera image is derived by generating one transition video then extracting a frame for free via scene detection (`get_new_camera_image`, `camera_image_generator.py:204-232` — PySceneDetect split, first frame of Scene-002, else last frame). One camera image amortizes across all shots on that camera.

**Priority-batched concurrency**: `asyncio.gather` fan-out (301, 485-486) with `priority_tasks` vs `normal_tasks` (441-486) and `asyncio.Event` frame→video dependencies (502-504) so video gen starts the moment its frames land — wall-time, and thus iteration-cost, reduction.

**Cheap-model routing + rate caps** (`configs/script2video.yaml`): chat model is `google/gemini-2.5-flash-lite-preview-09-2025` (line 3); per-service `max_requests_per_minute: 2` / `max_requests_per_day: 50` on image and video generators (19-20, 27-29) — a hard daily spend ceiling. `agents/best_image_selector.py` (prompt 13-43, schema 52-58) is a VLM pick-best-of-N-candidate-images judge (currently defined but not wired into the shipped pipelines) — cheap image-level selection before video spend.
