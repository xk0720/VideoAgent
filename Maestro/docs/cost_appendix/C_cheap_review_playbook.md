# Cheap-Review Playbook for Maestro (ranked by cost-saved × reliability), 2025–2026 evidence

## 1. Deterministic ffmpeg/ffprobe pre-checks — free, catch catastrophic failures before any VLM token is spent

Highest ratio: zero marginal cost, near-perfect reliability on the failure classes they cover.

- **Black frames**: `blackdetect` scans a whole file and reports every frame-group above a black threshold with timestamps ([ffmpeg blackdetect writeup, GDELT](https://blog.gdeltproject.org/using-ffmpegs-blackdetect-filter-to-identify-commercial-blocks/)).
- **Frozen frames**: `freezedetect=n=0.003:d=2` flags stretches where the picture stops changing; **silence**: `silencedetect` for dead audio. All three are wrapped with SMPTE-timestamp output in the open-source [frame-checker](https://github.com/kuvk/frame-checker) tool.
- **Mid-shot scene cuts** (a generated shot should have zero internal cuts): `scdet`/`select='gt(scene,T)'` per the [FFmpeg scene-detection cookbook](https://ffmpeg-cookbook.com/en/articles/scene-detect/), or [PySceneDetect](https://github.com/Breakthrough/PySceneDetect) (`pypi scenedetect`, content-aware detector) for a Python API. Any detected cut inside a 5–10 s shot is an automatic reject — no VLM needed.
- **Duration/stream anomalies**: ffprobe duration vs requested duration, missing audio stream, fps/resolution mismatch are trivial JSON checks (same toolchain as above).

Implementation cost: one `ffmpeg -vf blackdetect,freezedetect,scdet -af silencedetect` pass per shot (~1–2 s CPU at 480p). Route only shots that pass to any model-based review.

## 2. Fix the Gemini token knob you already control — `videoMetadata.fps=5` is a 5× cost *increase*, not a reduction

The fps parameter changes how many frames are sampled; tokens are billed **per frame**, so fewer fps = fewer tokens.

- Default sampling is **1 FPS**; custom fps via `videoMetadata` (`fps=5` is literally the docs' example of *raising* it; "low FPS (< 1)" is recommended for static content) — [Gemini video-understanding docs (legacy/customization section)](https://ai.google.dev/gemini-api/docs/generate-content/video-understanding), [current doc](https://ai.google.dev/gemini-api/docs/video-understanding).
- Token math ([same docs](https://ai.google.dev/gemini-api/docs/video-understanding)): **258 tokens/frame** default media resolution, **66 tokens/frame** at `media_resolution: low` (≈300 vs ≈100 tokens per second of video at 1 FPS), +32 tokens/s audio. **Gemini 3 models: 70 tokens/frame at default/low/medium, 280 at high** — low and medium are identical for video ([media-resolution doc](https://ai.google.dev/gemini-api/docs/media-resolution)).
- Concrete per-shot cost, 10 s shot: at fps=5 → 50 frames. Gemini 2.5 Flash default res: 12,900 video tokens ≈ **$0.0039** input at $0.30/M; at fps=1 + low res: 660 tokens ≈ **$0.0002** — a ~20× cut per review. Gemini 3.5 Flash ($1.50/M in, $9/M out) at fps=5: 3,500 tokens ≈ $0.005 in; at fps=1: $0.001. Pricing from the [official Gemini pricing page](https://ai.google.dev/gemini-api/docs/pricing): 3.5 Flash $1.50/$9.00, 3.5 Flash-Lite $0.30/$2.50, 2.5 Flash $0.30/$2.50, 2.5 Flash-Lite **$0.10/M input (text/image/video)**/$0.40 out; Batch/Flex halves input. Output/thinking tokens likely dominate once video input is trimmed — cap thinking and response length.
- Caveat: keep fps≥2–5 only for the checks that genuinely need motion (see §6). [Artifact-Bench](https://arxiv.org/html/2605.18984v1) itself samples at 5 fps for artifact tasks.

## 3. Cascaded judging: flash-lite prefilter → full native-video judge only on suspects

- Cascade literature is unambiguous: [FrugalGPT-style chains + cost-effective LLM-judge techniques](https://arxiv.org/html/2604.13717) reach ~85.8% judge accuracy cheaply; [Cluster–Route–Escalate](https://arxiv.org/html/2606.27457) retains **97–99% of strongest-model accuracy** with escalation only on low-confidence cases; [decision-theoretic cascade analysis](https://arxiv.org/pdf/2605.06350) formalizes the deferral threshold; RouteLLM/routing surveys report **75–98% cost reduction at ~95% quality** ([TrueFoundry overview](https://www.truefoundry.com/blog/llm-routing-cost-quality-aware-model-selection), [TianPan summary](https://tianpan.co/blog/2025-11-03-llm-routing-model-cascades)).
- Concrete tiering: 2.5 Flash-Lite (video input at $0.10/M tokens, ~660 tokens per 10 s shot at 1 fps low-res ≈ **$0.00007**) as pass/fail gate with a strict "escalate if any doubt" rubric; full-fps 3.x Flash review only on flagged shots. The blind A/B verifier (2 videos/call) is the most expensive call — run it only after the cheap gate disagrees with the generator, and at 1 fps/low res since A/B preference is a coarse judgment.
- Reality check on the expensive judge's value-add: on [Artifact-Bench](https://arxiv.org/html/2605.18984v1) (19 MLLMs incl. Gemini 3.1 Pro / 3 Flash) the **best model hit only 47.5% overall**; fine-grained artifact identification collapses to **<10% accuracy for almost all models** (humans: 87.7%). Frontier-model premium buys little on fine artifact diagnosis — coarse defect gating with a cheap model loses less than intuition suggests. [Q-Bench-Video (CVPR 2025)](https://openaccess.thecvf.com/content/CVPR2025/papers/Zhang_Q-Bench-Video_Benchmark_the_Video_Quality_Understanding_of_LMMs_CVPR_2025_paper.pdf) is the benchmark to sanity-test any tier swap.

## 4. Embedding-distance anchor and continuity checks (free-ish GPU, no API)

- First-frame-vs-pin check: cosine distance between DINO/CLIP embeddings of shot frame 0 and the conditioning anchor. This is exactly the machinery VBench uses for **subject consistency (DINO features)** and **background consistency (CLIP features)** across frames, validated at >90% correlation with human preference ([VBench, arXiv 2311.17982](https://arxiv.org/abs/2311.17982); [code, Apache-2.0](https://vchitect.github.io/VBench-project/); [VBench++ 2411.13503](https://arxiv.org/abs/2411.13503)).
- Same per-dimension implementations give free flicker/motion checks: **temporal flickering** = mean inter-frame pixel MAE on static regions; **motion smoothness** = AMT frame-interpolation reconstruction error; **dynamic degree** = RAFT optical-flow magnitude (catches "pretty but frozen" outputs) — details in the [VBench CVPR supplemental](https://openaccess.thecvf.com/content/CVPR2024/supplemental/Huang_VBench_Comprehensive_Benchmark_CVPR_2024_supplemental.pdf).
- Q-Router's Tier-2 shows handcrafted features (motion residuals, sharpness, gradient kurtosis, edge density) can *pre-localize* suspect frames before any VLM sees them ([Q-Router, arXiv 2510.08789](https://arxiv.org/html/2510.08789v1)).

## 5. Open reward models / VQA scorers as prefilters

- **VideoScore2** (Qwen2.5-VL-7B, trained on 27k scored videos; pointwise 1–5 on visual quality / text alignment / physical consistency) — [github.com/TIGER-AI-Lab/VideoScore2](https://github.com/TIGER-AI-Lab/VideoScore2/), [paper](https://arxiv.org/pdf/2509.22799).
- **VisionReward** (CogVLM2-Video-13B; interpretable checklist scoring; **+17.2% over VideoScore** on video preference) — [HF paper 2412.21059](https://huggingface.co/papers/2412.21059).
- **VideoReward / VideoAlign** (Qwen2-VL-**2B** on 182k human pairwise labels — small enough for cheap local inference) — [Improving Video Generation with Human Feedback, arXiv 2501.13918](https://arxiv.org/html/2501.13918v2).
- **Q-Router** ensemble of classical VQA experts (COVER, DOVER++, UVQ, MaxVQA, ModularBVQA, T2VQA): PLCC 0.8539/SRCC 0.8407, >20% over individual baselines; its Tier-2 **beats GPT-4o on Q-Bench-Video (60.07 vs 56.91)** using mostly non-frontier components ([arXiv 2510.08789](https://arxiv.org/html/2510.08789v1)). A 2B–7B local scorer thresholded loosely ("bottom quartile → escalate") is a plausible replacement for the per-shot Gemini pass on clearly-good shots.

## 6. How few frames suffice — evidence for sparse-frame gating

- **Single/few frames go far**: ATP shows a single-frame atemporal probe matches or beats video-language SOTA on many benchmarks ([Revisiting the "Video", arXiv 2206.01720](https://arxiv.org/abs/2206.01720)); single-frame training + multi-frame ensembling matches video models ([Lei et al., arXiv 2206.03428](https://arxiv.org/pdf/2206.03428)). Common video-LLMs ship with 8-frame or 1–2 FPS sampling ([F-16 paper background](https://arxiv.org/html/2503.13956v1)).
- **But motion defects need density**: 16-FPS sampling (F-16) sets SOTA on Video-MME/MLVU precisely because low FPS loses fast-motion information ([arXiv 2503.13956](https://arxiv.org/pdf/2503.13956)); Artifact-Bench attributes temporal-artifact failures to "sparse frame sampling and coarse temporal modeling," and localized artifacts to visual-token compression ([2605.18984](https://arxiv.org/html/2605.18984v1)). Practical split: sparse (4–8 frames, low res) for composition/identity/prompt-adherence gating; native 5 fps reserved for escalated motion/continuity review. Adaptive keyframe selection ([AKS, CVPR 2025](https://github.com/ncTimTang/AKS)) if you want smarter than uniform.

## 7. Generation-time early rejection (WaveSpeed/Seedance)

- WaveSpeed predictions are async: submit → prediction ID → poll to terminal status; **failed generations are not charged**, so a cheap post-hoc reject wastes only wall-clock, not generation dollars ([Seedance 2.0 async/retry guide](https://wavespeed.ai/blog/posts/blog-seedance-2-0-api-async-retries/), [Seedance 2.0 mini API guide](https://wavespeed.ai/blog/ai-api-pricing/seedance-2-0-mini-api-guide/)).
- Retry taxonomy from the same guide: transient 5xx/timeouts → retry identical request with idempotency key + backoff; validation/moderation errors → do **not** blind-retry, edit the input. The [Segmind Seedance 2.0 error guide](https://blog.segmind.com/seedance-2-0-error-guide-every-error-explained-with-fixes/) maps every error class (content moderation vs parameter vs infra) to the fix — encode this so a moderation failure triggers a prompt rewrite, not a full brain re-decision.
- `seed` is exposed on the model endpoints ([WaveSpeed Seedance 2.0 T2V model page](https://wavespeed.ai/models/bytedance/seedance-2.0/text-to-video), request/response schema at [wavespeed.ai/docs](https://wavespeed.ai/docs/docs-api/bytedance/bytedance-seedance-2.0-text-to-video)): on soft failures keep the seed and mutate only the prompt/conditioning (cheap, preserves the good parts), change seed only when the failure is compositional.

**Suggested pipeline order**: ffmpeg gate (§1, free) → embedding anchor/flicker checks (§4, free) → flash-lite sparse-frame gate (§3, ~$0.0001/shot) → full-fps Gemini 3.x Flash review only on suspects at corrected fps/media_resolution (§2) → blind A/B verifier only on repair candidates. Expected effect: VLM review spend drops to the suspect fraction (typically 10–30% of shots per cascade literature) × a per-call cost already cut ~5–20× by §2.
