§0 图例:四种零件

先打个比方:整条线像一个剧组。脑动嘴皮子做决定,眼看片子挑毛病, 尺是不带模型的硬规矩(它保证脑抽风时片子照样能拍完),手是真花钱出画面的后端。

脑 · LLM
纯文本严格 JSON 决策。出格/不可解析一律走确定性优先级兜底,并在 brain_calls.jsonl 记 via=fallback。
眼 · VLM
读画面/读视频。铁律是没看到就不编——拿不到回包就返回空,由上游诚实记"零证据"。
尺 · 确定性
不含任何模型的规则、闸门与打分。脑全挂了,这条线仍能出片,只是质量降级且日志刺眼。
手 · 生成后端
可灵 / seedance(视频)、flux(t2i)、seedream(图编)、ace-step(音乐)、ffmpeg(剪接)。

§7 生产 vs RL 训练环境

rl/env/ 是这条线的逐字移植(带函数级同构锁)。两边不一样的只有下面这张表—— 其余每一段(§A0 到 §E、交界分诊、缝合师、图计划、条件菜单与 ref2v 锁、提示词链、诚实降级)全部逐字相同。

组件生产RL 训练环境为什么
修复小循环 §D开(3 回合)关(整块不导入)训练要的是"第一次就写对"的信号,修复会把它洗掉
评审团 + 验收官 + 整理员开换成奖励判官训练用我们自己的 VLM 评分 skill,不用生产语义评审
锦标赛开(n=1 时空转)关胜者 = 组内奖励 argmax
片段记忆 §M开硬编码为空 guidance训练不能让历史片子污染同分布采样
润色师 / 过渡桥 / BGM / 基线锚点 / 原生对白按需开全关都不在被训练的决策路径上,纯成本
K 路条件采样不存在(2026-08-19 移除)RL 专有GRPO 的组来源
并发池不存在RL 专有rollout 吞吐

§8 六件最容易记错的事

  1. 人物抽取和场景图提示词走的是通用 models.llm,不是它们"看起来该有"的 crew 槽。 想给它们单独换型号,得先在 window_loop.py:3912 / :4018 加槽位。
  2. 锦标赛评委和接点实况观察走通用 models.mllm,不是 crew.reviewer。 换评审模型时这两个不会跟着变。
  3. 评审/验收的 SKILL.md 只是文档,不是活提示词。 真正发出去的是 mllm_backends.py 里的 _SHOT_REVIEW_INSTRUCTION 和 _VERIFY_PAIR_INSTRUCTION。 改了 SKILL.md 而线上没变化,原因就在这。
  4. 整理员的 skill 文件在 src/maestro/skills/ 里不存在(只在 skills_backup/), 所以润色那一步永远走内联兜底。
  5. 语义评审和物理评审共用一次上传 —— 按 (路径, mtime) 缓存,一次 API 调用出两份判词。别按两次计费估算成本。
  6. best.accepted = True 只表示"发货了",不表示"没毛病"。 真话在 converged + stop_reason + review_evidence 三个字段里。
